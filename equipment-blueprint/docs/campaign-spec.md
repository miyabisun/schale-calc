# 任務（Campaign）の仕様

BlueArchive の「任務」ステージに関する前提知識と、本リポジトリでのデータ整形方針をまとめる。

## ゲーム仕様

### 任務の種別
- 任務には **Normal** と **Hard** の2種類がある。
- 2倍キャンペーンはそれぞれ独立。
  - ある週は **Normal の報酬が2倍**
  - 別の週は **Hard の報酬が2倍**
  - 同時に2倍になる週はない前提で計算する。

### AP（スタミナ）
- AP は 1 時間に 10 ポイント回復するスタミナ。
- 1 回の出撃で消費する AP は種別で固定。
  - **Normal: 10 AP / 周**
  - **Hard: 20 AP / 周**

### 任務 X-Y の表記
- `任務X-Y` の **X** は `Area` (JSON フィールド)、**Y** は `Stage` に対応。
- 基本的に Y は 1〜5。X が 3 の倍数のエリアにのみ、5 の次に `"A"` の高難易度挑戦ステージが存在する（本リポジトリの計算対象外）。
- 表記は**オミット後も元の番号を保つ**（`任務2-5` の次は `任務4-1`）。詰めると UI 表示とズレて事故るため。

### Normal ステージの規則性（Area 単位）
Normal ステージはエリア番号を **3 で割った余り** で傾向が決まる。実データで検証済み。

| Area mod 3 | ドロップ傾向 |
|-----------:|--------------|
| 1          | 攻撃系の装備（Hat / Gloves / Shoes 等）。Tier1 完成品 または Tier2〜 設計図。 |
| 2          | 支援系の装備（Hairpin / Badge / Watch / Bag 等）。Tier1 完成品 または Tier2〜 設計図。 |
| 0          | 装備はドロップしない**チャレンジエリア**。`Stage "A"` もここにのみ存在。 |

## 報酬データの読み取りルール

`stages.json` の `Rewards[]` は以下のように解釈する。

### `RewardType`
| 値          | 意味                              | 本計算での扱い |
|-------------|-----------------------------------|----------------|
| 未指定      | 毎クリア時に抽選される通常ドロップ | **採用**       |
| `FirstClear`| 初回クリアのみ                    | 除外 (クリア済み前提) |
| `ThreeStar` | 三ツ星クリア初回のみ              | 除外 (同上)    |

### `Type`
| 値            | 概要                                                         | 本計算での扱い |
|---------------|--------------------------------------------------------------|----------------|
| `Currency`    | クレジット等。200〜800 程度で誤差レベル。                    | 除外           |
| `GachaGroup`  | 低価値素材のランダムプール。武器強化素材は含まれない。        | 除外           |
| `Equipment`   | 装備または装備設計図。Tier10 強化時に 60 個単位で要求される。 | **採用**       |

### 装備 ID の規則
装備 ID には 2 系統ある。

| パターン     | 例                        | 意味                          | 本計算での扱い |
|--------------|---------------------------|-------------------------------|----------------|
| `NNNN` (4桁) | `1000` 無地のキャップ     | **Tier1 完成品**。任務1,2 でほぼ無限に出るため育成上は余る。 | 除外         |
| `XXYYYY` (6桁, XX≠50) | `101001` ニット帽の設計図 | **Tier 2 以降の装備設計図**。Tier 値は `equipment.json` の `Tier` フィールドから取得する（ID 頭二桁は内部コードで、表示 Tier とは一致しない）。 | **採用** |
| `50YYYY`     | `501000` 帽子の万能設計図 | **万能設計図**。カテゴリ (Hat/Gloves/...) ごとに 1 種類。どの Tier の設計図にも交換可能で、レートは Tier 依存（例: Tier5 設計図 1 個 ⇔ 万能設計図 10 個）。`equipment.json` 上は `Tier: 0` として扱われる。 | **採用**         |

> 実装では `id >= 100000`（6桁）を採用条件にして、4桁 の Tier1 完成品だけを切り落としている。

### `Chance` / `Amount` の解釈
- `Chance` **未指定** ＝ 確定ドロップ（= 1.0）。
- `Chance` **数値** ＝ そのスロットのドロップ確率。
- 複数スロットは**互いに独立**抽選（排他ではない）。運が良ければ全部出るし、悪ければ全部出ない。
- したがって期待値は `Σ(slot.amount × (slot.chance ?? 1))` で単純合算できる。

## 計算対象の絞り込み

**採用するステージ**:
- `Category === "Campaign"`
- `Difficulty === 0`（Normal）
- `Area % 3 !== 0`
- 上記ルールで装備設計図が 1 種以上ドロップする

**オミットするステージ**:
- Hard 全般 (`Difficulty === 1`)
- 3 の倍数 Area 全般（`Stage "A"` を含む）
- Tier1 完成品（4桁ID）しか出ないステージ（任務 1-1〜2-5 に該当）

## 出力 YAML の構造（`data/campaign-normal-rewards.yaml`）

```yaml
stages:
  - label: "任務X-Y"         # ゲーム内表記
    area: <int>
    stage: <int>
    drops:
      - id: <equipment_id>
        name: <日本語名>
        category: <Hat / Gloves / Shoes / Hairpin / Badge / Watch / Bag / ...>
        tier: <0 = 万能設計図, 1 = 完成品(今回は出現しない), 2〜10 = 設計図>
        expected: <float>    # 同一IDの全スロット合算の期待ドロップ数
        slots:
          - amount: <int>
            chance: <float|unset>
```

## 既知の非対応・未対応

- **「簡易攻略／集中指揮」のフラグは `stages.json` に含まれていない**。3 ツ星クリア済みの Normal 任務なら基本的にどれも簡易攻略可能と想定して計算する。
